# Final game submission checklist

Status: planned requirements for the next build. The handoff archive is complete only as instructions and source material. It is not the completed game submission.

## Required final payload

- [ ] Complete print-and-play PDF, including every required cutout and mat.
- [ ] Separate replacement cutout sheets, one-page player guide, assembly/setup guide, full rules and blank workshop record.
- [ ] Accurate component inventory with actual page numbers, dimensions, quantities and clear spare counts.
- [ ] Matching browser game with all runtime assets and a clear local launch path.
- [ ] Reconciled final rules, design decisions and current design workbook.
- [ ] Shared editable content and rules data used by both media.
- [ ] Editable game and print-generation sources, build instructions and packaging tools.
- [ ] Final art files, provenance/generation records, fonts and applicable licenses.
- [ ] Both original supplied DOCX files and user-clarification record under provenance sources.
- [ ] Current automated/browser/PDF checks and a separate honest human workshop checklist.
- [ ] Opening document, release notes, file inventory and SHA-256 manifest.
- [ ] One self-contained all-files ZIP, rebuilt after the final print/game changes.

## Physical workshop release gates

- [ ] One printed master kit supplies a complete player station without downloading extra components.
- [ ] Six destination maps are present, plus a separate starting shore.
- [ ] The facilitator can order maps and handle Foresight with concealed future choices.
- [ ] Four ordinary seats, Soldier's second seat and zero-seat PoLong instances are obvious on the table.
- [ ] Ordinary soul recycling and renewable memory rewards work with the supplied physical pieces.
- [ ] Global spawn timing, anger and once-per-run quest state can be tracked without a computer.
- [ ] Color A4, single-sided, actual-size instructions, safe margins and calibration check are printed.
- [ ] Final PDF pages were all rendered and visually reviewed; component counts match the inventory.
- [ ] An actual-printer/cutting/handling checklist is supplied. Unperformed human checks remain NOT_RUN.

## Digital package release gates

- [ ] Exact packaged browser/rules/print files use the same current shared content hash.
- [ ] Game and printed rules have no three-cycle cap, finite arrival exhaustion, fixed delivery victory target or old persistent-wraith fog.
- [ ] ZIP CRC, membership and every payload byte match the staging folder.
- [ ] Extracted opening-page links and runtime asset paths resolve.
- [ ] No personal saves, unrelated files, `.git`, caches or obsolete game packages are included.
- [ ] The complete kit and the all-files ZIP are linked in the final delivery to the user.

## User-held submission details

- [ ] Confirm required portal and due date, including timezone.
- [ ] Confirm file-type and size limits, required filenames and any rubric.
- [ ] Add supplied course/team identifiers if required; do not invent them.
- [ ] Record actual archive size and whether it fits the supplied limit.
- [ ] Upload only if separately authorized; otherwise hand the checked ZIP to the user.
- [ ] Record a real submission receipt before claiming submitted.
