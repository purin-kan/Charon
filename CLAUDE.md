## Desktop v0.8.1 layout

All paths below are under `outputs/The_Ferryman_Desktop_v0.8.1/`. The folder is self-contained and depends on no other folder.

- `rules/`: the rules source copied from the v0.7 quest trial. `content.json` is the editable source; `content.js`, `rules.json` and `RULES.md` are generated by `node tools/build-content.js`; do not edit them by hand. `engine.js` is a UMD module (`Ferry`: create, transition, validate and helpers). Edit it only for rule changes, never to fix loading.
- `src/ferry.js` loads `rules/content.js` then `rules/engine.js` and exports `Ferry` (falls back to the CommonJS export in a production Vite build). `src/router.js` and `src/phase-map.js` map `state.phase` to scenes and wait for `router.exitDone()`. `src/scenes/` has one file per scene, listed in `src/scenes/index.js`. `src/dev/` holds the dev launcher and fixture states. `src/preloader.js` loads assets by file name with letter-emblem and silence fallbacks.
- `assets/`: `art/`, `backgrounds/`, `audio/`, `fonts/` (Vera), `tuning.json` (presentation timings only, never read by the engine) and `source-art/` (v0.7 art for sprite cut-outs, not runtime assets).
- Only the scaffold owner (purin-kan) changes `src/scenes/index.js`, `package.json` and the lockfile.

## Launch and verification

From the desktop folder: `npm install`, then `npm start` (Electron Forge dev window). `npm run check` runs the engine, fixture-mapping and dispatch checks; `npm run fixtures` regenerates `src/dev/fixtures/`. From `rules/`: `node tools/build-content.js` and `node tests/quest-check.js` (writes `rules/verification/quest-results.json`). Record results in `STATUS.md`. Packaging (`npm run package`, `.exe`) is Scaffold B and not yet verified. Do not replace NOT_RUN entries with inferred results.

## Repository layout

- `notes/`: plan, task register, decisions, engine comparison and team ideas. Earlier suggestions are not current rules.
- `history/`: dated agent checkpoints and older handoffs. `sources/`: original concept text. `Gamelist/`: soul and memory reference lists.
- Use ignored `work/` or `temp/` for scratch files. Local tool-state directories are not deliverables. Never commit `out/`, `dist/`, `.vite/` or `node_modules/`; Electron builds exceed GitHub's 100 MiB file limit.
